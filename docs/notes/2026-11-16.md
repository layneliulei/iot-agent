# 2026-11-16 · S3 Day 1 语料 / 切片 / 入库

## 卡在哪
- `python -m app.rag.index --probe` 在 `STEncoder()` 实例化处崩：`OSError [WinError 126] … torch\lib\c10.dll`。
  建库一行都没跑成，`collections=[]` 是空的。

## 为什么
- 本机缺 Microsoft Visual C++ Redistributable，torch 的 `c10.dll` 加载不了。
  不是缺包（三个包都 `already satisfied`），也不是网络或模型下载（还没走到那一步）。
- 中途被 `Object of type "None" is not subscriptable` 带偏去查 `payload`；
  真正把范围收回来的是 `collections=[]`——空集合说明崩溃发生在**建库之前**。

## 怎么解
- 装 VC++ 2015–2022 x64 redist → 重开 PowerShell → `python -c "import torch"` 得 `2.15.0+cpu`
  → 重跑同一条命令，`41` / `43` 入库成功。没有管理员权限就改走 fastembed（`--encoder fast`）。

## 今日产出
- `docs/manuals/` 20 份 mock 手册（5 类设备 × 4 主题），每份 ≥3 个 `##` 小节。
- `app/rag/index.py`：两种切片（naive 500/0；struct 500/80 + `separators=["\n## ", …]`），
  `BAAI/bge-small-zh-v1.5`（512 维），入 Qdrant 两个 collection：
  `manuals_naive` 41 块 / `manuals_struct` 43 块，`points_count` 与切片数逐字相等；
  payload 带 `source / title / chunk_index / strategy`。
- probe 对比：「上报间隔是多少?」struct 首条是 `battery-manual#2`「三、上报间隔」整节（0.5724），
  naive 最好只有 0.4920 且文本从句子中段开始 → **两种切片的差别在「从哪里切开」，不在「切多少」**
  （41 vs 43 只差 2 块，多数 `##` 小节不足 500 字被合并）。
- 负样本「这个设备的出厂价是多少?」两种策略都返回 3 条（最高 0.4637）→ 召回层没有阈值，
  「材料不足就说不知道」只能靠 generate 层的 prompt 约束。
- 顺手修：`authorize` docstring 写错语义（`None` 才是放行）；`tool_node` 注入的 `tenant_id` 原来被丢弃
  （真链路 `keys=['t1:…']` → 加 `tool_call = {**tool_call, "args": args}` 后 `['t2:…']`）；
  `"toll_call"` 拼写；README `# 10 passed`；`Q_PREFIX` 的「已→以」；`--encoder` 收窄为 `["st"]`。
- `python -m pytest -q` = `10 passed`。

## 附记（不是卡点）
- 模型被要求建单时先查设备、拿到「未找到」后**先确认再写**，`keys=[]`——写操作的保守行为，不是 bug。
- `_DEVICE_TENANT` 有 `DEV-003`(t2)，`get_device_status` 的假数据只有 `DEV-001/002`
  → 两处 mock 不一致，「台账里有、查询说未找到」。
- Pylance 提示 `h.payload: Payload | None`：本次报错与它无关，但 `p = h.payload or {}` 留着更稳。
- 语料约 1.5–2 万字、候选池只有 41/43 块 → D3 的 20 条评测命中率会天然偏高，
  **以后引用数字必须带上语料规模这个前提**。
