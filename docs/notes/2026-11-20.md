1. `app/main.py` 里根本没有 RAG 的路由。`rag_graph` 写完了、20 条评测 82% 也跑出来了，
   但它只活在 `python -m app.rag.graph` 里 —— 服务起来只有 `/health` 和一个直接
   `llm.ainvoke` 的 `/chat`，部署出去是个空壳。
2. 补完 `/ask` 后宿主 500：`OSError: 页面文件太小，无法完成操作。(os error 1455)`，
   抛在 `CrossEncoder("BAAI/bge-reranker-base")` 加载处。前面 `Loading weights: 100%|71/71`
   说明 bge-small-zh 已经装好了，挂在第二个模型上。
3. 容器起来、端口映射 `0.0.0.0:8001->8000` 正常、`docker logs` 只有 startup 三行，
   宿主一打 8001 就是 502，请求根本没进容器。

## 为什么
1. 进程内对象图 ≠ HTTP 契约。「脚本跑通」只证明链路对，「别人能访问」走的是另一条路径
   （请求模型 → 图 → 检索 → 出处），中间任何一环没接，外面看到的就是空壳。同一个毛病
   上一轮刚犯过一次：`eval/dataset.jsonl` 被 .gitignore 挡住没入库，README 那张表别人
   clone 下来跑不出来 —— 都是「写了不等于生效」。
2. 1455 是提交内存不够，不是代码 bug：torch + 两个 bge 模型 + 常驻 uvicorn +
   Docker Desktop 预占的 commit 叠在一起越过了 Windows 提交上限。重试能过是因为缓存
   放热了，问题并没有消失。
3. httpx 会读环境变量里的代理，把 `127.0.0.1:8001` 当外网发出去，代理连不上就回 502。
   而「容器 Up、端口映射在」这两条都不足以证明链路通 —— 只有 `docker logs` 里那条
   `POST /ask 200` 才算证据。

## 怎么解
1. 加 `POST /ask`：请求模型 → `rag_graph.ainvoke` → 返回 `answer` + `sources`（文件名#块号）
   + `usage`。判据三条：正常问句带出处；精确问句只落对应设备（`BST-48F` → 只出 `battery-*`）；
   负样本「公司的报销流程是什么?」回「材料中没有相关信息。」且 `sources` 为空 —— 第三条
   才证明是真检索，不是模型自由发挥。
2. 1455：先关 Docker/WSL 释放提交内存，再调大页面文件（虚拟内存 8192/24576 MB）。
   `RERANK=kw` 只能当应急，它会把 82% 的复现条件改掉。
3. 502：`$env:HTTP_PROXY=""; $env:HTTPS_PROXY=""; $env:NO_PROXY="localhost,127.0.0.1"`，
   再 `setx NO_PROXY` 固化。判据从「容器 Up」换成「`docker logs` 出现 `POST /ask 200`」。
4. Qdrant 地址改 `os.getenv("QDRANT_URL", "http://localhost:6333")`，容器用
   `host.docker.internal:6333` 连宿主上已经在跑的库 —— 部署当天不重建索引。
5. 容器四个参数各治一个问题：`QDRANT_URL` / `HF_ENDPOINT=hf-mirror` /
   挂宿主 `~/.cache/huggingface` / `.env` 只读挂载（key 不进镜像，`.dockerignore` 已排除）。
6. 首次 build 65 分钟，其中 pip 装 torch 单项 64 分钟；之后改 Python 代码只重建最后的
   `COPY` 层，秒级。
